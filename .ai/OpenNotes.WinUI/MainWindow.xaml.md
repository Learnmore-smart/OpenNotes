# OpenNotes.WinUI/MainWindow.xaml
> Last updated: 2026-09-26 (T12-A Fluent window chrome — unified chrome band + Mica region) | Protection: STANDARD

## Purpose
WinUI 3 `Microsoft.UI.Xaml.Window` markup (NOT WPF `System.Windows.Window`) — the V6 chrome: a single Fluent chrome band (brand + nav cluster, tab strip, caption buttons on ONE row), a translucent band surface for the window `SystemBackdrop`, per-tab `Frame` host area, home toolbar row, and toast overlay.

## Layout
- `RootGrid` (**Background=Transparent** — transparent still hit-tests, null would not): Row0 = `ChromeBand`, Row1 = `TabContentArea` (opaque `ThemeWindowBrush`; this opaque content is what confines the system backdrop to the chrome band — Mica must NEVER read over the document workspace).
- **ChromeBand** (`Border`, bottom `ThemeBorderBrush` hairline): its Background is resolved in code-behind (`ApplyChromeSurface`) — translucent `ThemeChromeBrush` while a `SystemBackdrop` is installed, opaque `ThemeToolbarBrush` otherwise (translucent pixels with no backdrop composite as black — never let the band stay translucent when `_systemBackdropInstalled` is false). Contains a 2-row grid: Row0 = the chrome row, Row1 = `HomeToolbarPanel`.
- **Chrome row (44px):** `AppTitleBar` Grid (`SetTitleBar` drag surface) = 3 columns — Auto brand/nav cluster (`BrandMarginRail` + product name + `NavBackButton`/`NavForwardButton`/`NavHomeButton`), `*` tab strip (outer `ScrollViewer` hugging content with `HorizontalAlignment=Left` so free space stays drag region; horizontal scroll kicks in on pill overflow), Auto right cluster (`MoreButton` flyout then `MinimizeButton`/`MaximizeButton`/`CloseButton`, all inside `CaptionButtonsPanel`). Interactive children stay clickable through the caption rect via framework passthrough.
- **Tab strip:** horizontal `ListView` (`TabStrip`, `ItemsStackPanel` horizontal, internal scroll disabled) + `NewTabButton` at strip end. Drag-reorder needs ALL of `CanReorderItems`+`CanDragItems`+`AllowDrop`; `IsItemClickEnabled` + single selection drives activation; `ItemsSource` binds `OneTime` (the `ObservableCollection` carries notifications). `ItemContainerTransitions` = `AddDeleteThemeTransition`+`RepositionThemeTransition`+`ContentThemeTransition` (built-in theme transitions are safe with reorder + middle-click close).
- Styles (all VSM + generated `VisualTransition`s ≤200ms — the animated element is a dedicated `StateLayer` Border whose Opacity the transition interpolates, since brush objects can't animate): `NavButtonStyle` (32×32, radius `ThemeRadiusControl`), `TabCloseButtonStyle` (24×24 hit area, radius 4), `TitleBarButtonStyle` (46×row-height), `CloseButtonStyle` (red hover #C42B1C / pressed #B22A1B, `Content.Foreground`→White, `0,8,0,0` corner for the rounded window corner), `TabListViewItemStyle` (bare transparent container — the pill paints all chrome), `TabItemTemplate` (`x:DataType AppTab`: 32px pill, `ThemeRadiusControl`, `TabHoverTint` StateLayer + icon + truncated title + hover-revealed `TabCloseButton` + `AccentBarVisibility` underline; `ScaleTransform` on the root so code-behind can press-scale 0.97; hover fade + scale run from code-behind so they honor `ShouldAnimate`).
- **Home toolbar:** `HomeToolbarPanel` sits in ChromeBand Row1 (its own band UNDER the chrome row — no longer packed into the caption cluster): `SearchBox` `TextBox` inside `SearchBoxBorder`, `SelectButton`, `SortButton` (flyout `SortByNameMenuItem`/`SortByDateMenuItem`). Code-behind collapses the panel unless the active page is `HomePage`.
- **Toast overlay (Task 5):** `ToastBorder` + `ToastIcon` + `ToastText` layered over `TabContentArea` inside `RootGrid` — `Visibility=Collapsed` + `Opacity=0` default, code-behind fades in/out; `IsHitTestVisible=False` so it never eats clicks.
- **Window file drop (Task 5 review fix):** `RootGrid` carries `AllowDrop` + `DragOver`/`Drop` → `Window_DragOver`/`Window_Drop` in code-behind. Events bubble from the deepest element — HomePage's own grid marks accepted drops `Handled`, so the window handlers only fire for drops HomePage declined or while a non-Home page is active (WPF `ShouldDeferWindowFileDrop` parity).

## Important Notes / NEVER Change
- **Caption fix (defect found in spec review of `dbfd81a`):** `ExtendsContentIntoTitleBar=true` alone does NOT remove the system Min/Max/Close — they render TOPMOST over the right edge and swallow real clicks (UIA Invoke passes anyway because it bypasses hit-testing). The custom buttons are the only true caption UI because code-behind calls `OverlappedPresenter.SetBorderAndTitleBar(hasBorder: true, hasTitleBar: false)` in `ApplyCustomChrome` (re-applied on `AppWindow.Changed`/`DidPresenterChange`). NEVER remove that call when editing chrome — if a future chrome rewrite recreates/swaps the presenter, re-apply there too.
- **Transparency rule:** `RootGrid` must stay `Transparent` and `TabContentArea` must stay opaque — the system backdrop reads through EVERY transparent pixel; only `ChromeBand` is allowed to be translucent. Do not paint a translucent brush anywhere else in the tree.
- `TabCloseButton` keeps `Opacity` (visual), `IsHitTestVisible` (click gate) AND `IsTabStop` (keyboard gate) bound to `AppTab` — an opacity-0 element still hit-tests AND stays keyboard-focusable/UIA-invokable by default; without the gates an invisible close button could swallow a tab-select click or take an Enter/Space close on an invisible target.
- WinUI `Window` has NO `Resources` property — all styles/templates live under `RootGrid.Resources`.
- `{ThemeResource}` is used everywhere (not `StaticResource`) so `WinUiThemeService` resource replacement re-renders chrome live.
- Lucide vectors are NOT ported yet: `FontIcon` glyphs stand in (E72B/E72A back/fwd, E80F home, E921/E922/E923 min/max/restore, E8BB close, E710 plus, E711 tab-close, E712 more, E8A5 doc) — swap when the icon port lands.
- All chrome `AutomationProperties.AutomationId`s (`AppTitleBar`, `NavBackButton`, `NavForwardButton`, `NavHomeButton`, `TabStrip`, `AppTab`, `TabCloseButton`, `NewTabButton`, `MoreButton`, `MinimizeButton`, `MaximizeButton`, `CloseButton`, `HomeToolbarPanel`, `SearchBox`, `SelectButton`, `SortButton`, `SortByNameMenuItem`, `SortByDateMenuItem`, `SettingsMenuItem`, `CheckForUpdatesMenuItem`, `AboutMenuItem`, `ToastBorder`, `ToastText`) are load-bearing for `tools/winui-uia-*.ps1` — x:Name alone does NOT surface as an AutomationId in WinUI.
- `x:Bind` is `OneWay` — it keeps no `BindingExpression`, so `PointerExited` must `SetValue` the computed `TabBackground` (NOT `ClearValue`, which would null the pill and strip the active tab's surface brush — regression fixed).
- No app icon `Image` in the title bar yet: `Assets/app-icon.ico` is ICO (WinUI `Image` can't decode it); the icon port should add a PNG.
